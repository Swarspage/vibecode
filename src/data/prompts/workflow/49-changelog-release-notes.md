49 — WRITING A CHANGELOG & RELEASE NOTES

We are releasing this change set: [describe the commits, PRs, or version].

Generate release notes suitable for both technical and non-technical readers.

Include:

1) a short summary of the release,
2) new features,
3) improvements,
4) bug fixes,
5) breaking changes and migration steps,
6) security updates,
7) contributors or teams involved,
8) links to relevant PRs, docs, and issues.

Follow the repo's existing changelog format if one exists. Keep the tone clear, professional, and honest. Do not overpromise or hide known issues.
